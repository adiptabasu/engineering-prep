# Progress journal

## Placement and structure
- Journals are optional. Never create personal journals or workspaces without agreement on exact paths, contents, and Git policy, and never store them in `skills/`.
- For multi-topic learning, keep `LEARNING-JOURNAL.md` as a small topic index + genuinely cross-topic notes only. Store topic history beside topic materials (`<topic>/LEARNING-JOURNAL.md`) in **newest-first** order using one compact entry format (no duplicate paragraph + summary table for the same item).

## Lean reads and updates
- On resume or update, start from the agreed learning home / Learning Brief. Read the central index only if the active topic path is unknown, and read only the **top ~30–40 lines** of the active topic journal (skip the topic README and unrelated journals unless needed).
- When recording a solved problem, keep it to 3–5 concise fields/lines: problem link + date, learner's proposed approach, guidance needed, learner-reported acceptance (`yes`/`no`/`not reported`), and 1 revisit point or open question.
- Keep learner reports distinct from demonstrated evidence (explanation, independent derivation, transfer, assessment). Never infer acceptance or mastery from a commit or submitted file. Capture confidence only if stated; frame difficulties as observations, not diagnoses.

## Review and migration
- If paths and update policy are agreed, write the concise update directly and share a ≤5-line summary for diff review; otherwise show proposed edits in chat first.
- When migrating a monolithic journal: inspect and inventory all entries/rows, map each to its topic (keeping ambiguous items in a hold section), preserve dates/links/uncertainty, fix relative links, verify source-to-destination counts, and get approval before removing the original.
- Keep private details out of tracked Git files unless explicitly chosen; never commit or push without separate authorization.
