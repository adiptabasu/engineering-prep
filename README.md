# Learning Philosophy

This repository is not intended to be a collection of memorized solutions.

For each problem, the objective is to understand:

- What is the problem actually asking?
- What is the brute-force solution?
- Why does the brute-force solution work?
- What makes it inefficient?
- What information can be reused?
- What data structure or algorithm can improve it?
- Why does the optimized solution work?
- What invariant are we maintaining?
- What are the time and space complexities?
- What variations of the problem could appear in an interview?
- What mistakes are commonly made?

Solutions should therefore be understood before they are considered complete.

# DSA Problem Structure

Each completed problem should eventually contain:

```text
Problem
Approach
Brute Force
Optimization
Key Insight
Why It Works
Implementation
Complexity Analysis
Common Mistakes
Interview Follow-ups
```

The repository should serve both as a record of solved problems and as a long-term revision resource.

# Progress Tracking

Topics will be marked as completed only when the underlying concept can be applied to unfamiliar problems, rather than simply when a fixed number of problems has been solved.

The objective is:

> Understand → Derive → Implement → Solve → Explain → Re-solve
